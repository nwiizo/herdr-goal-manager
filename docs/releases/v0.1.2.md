# herdr-goal-manager v0.1.2

Unattended goal loops you can review: a review flow with a packet and
verdicts from another provider, an optional factory queue, a watch that keeps
main working, and the provider's native goal (`/goal`) where it helps.

## Install

```sh
herdr plugin install nwiizo/herdr-goal-manager --ref v0.1.2
```

Or download `hgm-v0.1.2-<target>.tar.gz` for macOS or Linux (arm64, x86_64),
check it against `SHA256SUMS`, extract it, and run `herdr plugin link` on the
extracted folder. Or install from crates.io:

```sh
cargo install herdr-goal-manager --locked
hgm plugin-folder
herdr plugin link ~/.local/share/herdr-goal-manager/plugin
```

Bind `herdr-goal-manager.open` to a key (see the README).

## Changes

- Review flow: `hgm packet` (acceptance, checks with work-dir fingerprints,
  decisions, follow-ups, verdicts and what is not verified), reviewer roles on
  another provider with `loop.require_review`, write scope per task, and
  attention accounting from each goal's timeline.
- Factory mode (off by default): a queue of agreed contracts dispatched one at
  a time, each into its own checkout.
- Keeping main working: prepared steps handed over when main settles, idle and
  no-progress notices, goal checks, settle checks that wake the manager, and
  compact wakes that carry only what changed.
- Native goals: `loop.native_goal` (`assignment`, the default for new
  contracts; `settle`; `false`) sets Claude Code's `/goal` with the assignment;
  a Claude Code Goal Manager gets its own goal (`manager.native_goal`), waits
  for news with `hgm await`, and a spin guard clears it once when it keeps
  continuing with nothing to do.
- `loop.cross_check` (off by default): another provider checks the worker's
  work read-only each time it settles, and its verdict wakes the manager.
- Safety: input is never typed into a draft, a dialog or an unknown input line,
  and input that may have arrived is recorded as uncertain and never replayed,
  also across a watch that stopped mid-way; linked sends and the watch's
  continues stop at the goal's budgets, protected paths and stop checks.
  Verdicts and native-goal outcomes complete nothing and accept nothing.

See `CHANGELOG.md` for the full list and `docs/verification.md` for what was
checked natively and with controlled executables.

## Limits

`loop.cross_check` and the latest safety fixes are verified with controlled
executables, not yet natively. Native goals are Claude Code only; Codex and
Copilot stay off. See the README's Limits.
